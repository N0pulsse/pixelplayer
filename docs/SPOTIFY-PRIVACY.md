# Spotify в Pixel Player

Pixel Player — независимое приложение, не связанное со Spotify AB. Подключение необязательно и работает через официальный Spotify Web API и Spotify Connect. Для управления воспроизведением требуется Spotify Premium и доступ к приложению разработчика.

## Данные и доступ

- Приложение читает ваши плейлисты (включая приватные и совместные), сохранённые треки и альбомы, состояние воспроизведения и доступные устройства Spotify.
- По вашим действиям оно может запустить/приостановить музыку, переключить трек, перемотать, изменить громкость, повтор, перемешивание или выбрать устройство Spotify.
- Оно не запрашивает пароль, доступ к почте, изменение библиотеки или изменение плейлистов.
- Вход происходит на `accounts.spotify.com` через OAuth Authorization Code + PKCE. Для настольного приложения Client Secret не используется. Локальный callback слушает только `127.0.0.1:43827` и закрывается после входа, отмены или через 5 минут.
- Токены доступа и обновления шифруются Electron safeStorage (Windows DPAPI) и сохраняются в `spotify-session.bin` в профиле Pixel Player. Client ID не является секретом и сохраняется отдельно в настройках пользователя. На другом ПК требуется повторный вход.
- Метаданные библиотеки и устройств находятся в оперативной памяти приложения; библиотека Spotify не экспортируется в локальную коллекцию и не отправляется ИИ-агенту. Пароли и токены не публикуются на GitHub и не включаются в сборку.
- Запросы с токенами отправляются только на `api.spotify.com` и `accounts.spotify.com`. Обложки загружаются с серверов изображений Spotify. Ссылки на треки открываются на `open.spotify.com`. Сервер разработчика Pixel Player для этой функции не используется.

## Отключение

В разделе Spotify → настройки нажмите «Отключить аккаунт». Это удаляет локально сохранённые токены, очищает состояние подключения и отменяет незавершённый вход. Для отзыва разрешения на стороне Spotify удалите Pixel Player в [списке подключённых приложений Spotify](https://www.spotify.com/account/apps/).

## Ограничения

Аудио воспроизводится официальным клиентом Spotify или другим выбранным Spotify Connect устройством. Откройте Spotify, начните воспроизведение и обновите список устройств в Pixel Player. Встроенный потоковый декодер, скачивание музыки, обход DRM и офлайн-копирование треков не реализованы. Эквалайзер, скорость, кроссфейд, синхронизированные тексты и ИИ-агент Pixel Player применяются только к локальной музыке.

Управление через Connect зависит от разрешений, которые Spotify сообщает для текущего устройства и контекста. Если сервер возвращает `Restriction violated`, команды могут быть недоступны даже при активном Premium; интерфейс показывает отказ и учитывает флаги запрета действий Spotify. В этом случае используйте кнопку открытия трека/альбома/плейлиста в официальном Spotify. Наличие коллекции в Pixel Player само по себе не означает, что Spotify разрешил управление устройством.

Для личного использования создайте приложение Web API в [кабинете разработчика Spotify](https://developer.spotify.com/dashboard), укажите Redirect URI `http://127.0.0.1:43827/callback`, вставьте его Client ID в настройки Pixel Player и войдите. Не публикуйте Client Secret. В development mode пользователь должен быть владельцем приложения либо добавлен в список разрешённых пользователей Spotify; действуют квоты Spotify.

Вопросы и сообщения о проблемах: [репозиторий Pixel Player](https://github.com/N0pulsse/pixelplayer/issues).

## Восстановление запуска в 1.5.1

Pixel Player проверяет, что выбранная песня действительно играет. Если Spotify Connect не запускает её на выбранном ПК, плеер открывает проверенную ссылку `spotify:track:…` в установленном Spotify. Ссылка содержит только идентификатор музыки, без токенов доступа. Для телефона и колонок такое перенаправление не применяется. Если состояние не подтверждено, интерфейс сообщает об этом. Звук Spotify воспроизводится официальным приложением; Premium и вход в Spotify на ПК сохраняются необходимыми.

В 2.0 встроенный режим дополнительно запрашивает streaming, user-read-email и user-read-private, необходимые Spotify SDK. Access token доступен только изолированному аудиодвижку; refresh token остаётся в зашифрованном хранилище. Публичные EXE и исходники не содержат пользовательский вход. См. [описание стриминга](SPOTIFY-STREAMING.md).
